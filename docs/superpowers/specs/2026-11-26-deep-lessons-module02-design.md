# Module 02 deep lessons: design

**Status:** approved 2026-11-26. The owner chose 14 deep steps that keep every view (option A).
**Standard:** the same as Module 01 (`2026-11-25-deep-lessons-module01-design.md`, including its 2026-11-26 split-layout
amendment): six reading sections, a practice panel, the depth validator, Pyodide exercises, worked tables generated by
scripts, and "Run it locally" listings with captured output.

## Why

Curriculum v2 requires deep lessons in every module. Module 02 is the foundation for everything that follows:
- tokenization drives cost, context limits and failure modes;
- embeddings feed classification, clustering and RAG.

A learner who finishes it should be able to:
- write a BPE tokenizer;
- explain any real tokenizer's output;
- estimate token costs;
- build semantic search from embeddings.

## Exercises (Pyodide, NumPy only; 2–4 parts each)

1. Split a text by words, characters and UTF-8 bytes. Count the tokens under each scheme, and compute the vocabulary
   size each scheme needs.
2. Build a vocabulary with ids and `<unk>`, then encode and decode. Measure how much of an unseen text the vocabulary covers.
3. BPE training: count adjacent pairs, merge the most frequent, and loop. On the Sennrich corpus the result must equal
   the published merge order.
4. BPE encoding: apply the learned merges by rank to unseen words (`lowest`), then decode.
5. Bytes: UTF-8 encode and decode, compare byte counts per script (Latin, accented, CJK, emoji), and do byte fallback.
6. WordPiece: greedy longest-match-first encoding with `##` continuation pieces. Compute WordPiece's pair score vs BPE's frequency.
7. Unigram: find the best segmentation (Viterbi) from piece log-probabilities, and compare the scores of competing segmentations.
8. Special tokens: format a chat template, then pad and truncate a batch with an attention mask.
9. Real tokenizers: compute token tax ratios from recorded counts (real tiktoken/BERT counts in a fixture), and measure
   how numbers get split.
10. Cost and context: a token cost estimator, a context-budget check, and token-aware chunking with overlap.
11. The embedding table: look up rows, show that one-hot × matrix gives the same row, and count parameters for real models.
12. Contextual vectors: cosine similarity between real MiniLM "bank" token vectors. Show that a static table (one vector
    per word) cannot tell the senses apart.
13. Sentence vectors: mean pooling with an attention mask, L2 normalization, and a cosine similarity matrix on real MiniLM vectors.
14. Mini-project: a semantic search engine over real MiniLM sentence vectors (normalize, score, top-k with a threshold).
    Evaluate it with hit@1 on labelled queries.

## Run it locally (captured in Docker, exact pins)

- **tiktoken:** the GPT-4o encoding (`o200k_base`) on mixed text, with ids and pieces.
- **Hugging Face tokenizers:** train a small BPE tokenizer, and BERT's WordPiece on the same text.
- **sentence-transformers:** all-MiniLM-L6-v2 similarity matrix, and the "bank" token vectors from transformers.

## Data

Real MiniLM vectors (the existing fixture script) and real tokenizer counts (js-tiktoken and the BERT vocabulary
already in the repo) are generated into `deep/data/` by a script. No number is written by hand.
