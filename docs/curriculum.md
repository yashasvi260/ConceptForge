# CURRICULUM.md — LLM Mastery: End-to-End Interactive Syllabus (v2)

**Goal:** someone who works through this course understands how large language models work and can build with them:
use them, retrieve with them, fine-tune them, serve them and evaluate them. Every module ends with working Python the
learner wrote themselves.

**v2 (2026-11-26)** replaces the 14-module plan. What changed and why:

- **Every module uses the deep-lesson format** (below) instead of "one paragraph + a visualizer". The old format was
  too thin for anyone to implement what they learned.
- **Module 3 is split.** "Inside the transformer block" (attention, positions, norms, feed-forward, MoE) is now separate
  from "How LLMs generate" (logits, sampling, KV cache, long context).
- **New Module 5: How models learn.** Next-token loss, gradient descent and scaling laws. Part III (training) builds on it.
- **Agents get a module of their own** (Module 10). Quantization moves to serving (Module 16) and fine-tuning (QLoRA, Module 14).
- **RAG goes as far as real systems:** vector indexes (HNSW), metadata filters, query rewriting and agentic retrieval.
- **New Module 15: Reasoning models and distillation.** RL fine-tuning (GRPO), test-time compute, distillation, synthetic data.
- **New Module 18: Capstone.** One end-to-end build that uses the whole course.
- **The real-numbers rule:** no simulator invents latency, cost, memory or accuracy. Every number shown is computed in the
  page, measured in a captured run, or quoted from a cited source.

## The lesson format (every module)

Each step is a **deep lesson**, laid out as a split page:

- **Left: the reading, which scrolls.** It has six sections:
  1. **Why it exists:** the problem the idea solves (150–450 words).
  2. **Worked example:** one small case worked by hand with real numbers. Every table is generated by a script and tested.
  3. **The concept:** the full explanation (700–1,700 words). Each formula is built up term by term, with its symbols
     named, a worked number, and a "common mistake" note.
  4. **Build it:** a card that opens the exercise in the practice panel.
  5. **Check:** 2–3 questions answered in the page, each with an explanation.
  6. **In one sentence:** a one-sentence summary, plus 1–3 primary sources under "Go deeper".
- **Right: the practice panel, which stays in view.** It has two tabs:
  - **Interactive:** the step's live visualizer or simulator, with a guided "predict → change it → explain" task.
  - **Build it · Python:** a multi-part exercise that runs in the browser (Pyodide). Each part has starter code with
    `TODO`s, private checks, hints and a solution. Any code that needs PyTorch, Hugging Face or Ollama comes as a
    **"Run it locally"** listing, with exact `pip install` pins and its captured real output.
- **Per module:**
  - a **Practice Check** of 2–3 scenario questions;
  - a **recap step** with a mini-project that combines the module's parts;
  - a bridge card linking from the previous module and to the next.

Standards are enforced by tests (`core/deep.ts`, each module's `deep.test.ts`):
- every exercise solution passes its checks;
- every untouched starter fails cleanly;
- known wrong answers fail;
- every worked table equals its script's output.

## Part I: Understanding Language Models

### Module 1: Introduction to Language Models (`01-intro-llms`) — deep ✓
- **Concepts:** what an LLM is and how big it is, training vs. using a model, bag-of-words vs. dense embeddings,
  context, encoder-only vs. decoder-only vs. encoder-decoder models, representation vs. generative models,
  pre-training vs. fine-tuning.
- **Build:** a bigram language model with smoothing, temperature sampling and perplexity.

### Module 2: Tokens and Embeddings (`02-tokens-embeddings`)
- **Concepts:**
  - Tokenization at word, subword (BPE, WordPiece, SentencePiece/Unigram), character and byte level.
  - Vocabularies and special tokens.
  - The embedding lookup table.
  - Static vs. contextual embeddings.
  - Sentence embeddings and cosine similarity.
- **Interactive:** a real tokenizer playground (English, code, numbers, multilingual). A contextual-shift view
  showing "bank" in "approved the loan" vs. "river bank".
- **Build:** train BPE merges from scratch and encode new words with them. Look up embeddings and rank sentences by cosine similarity.

### Module 3: Inside the Transformer Block (`03-transformer-internals`)
- **Concepts:**
  - The forward pass, end to end.
  - Positional information (sinusoidal, RoPE).
  - Q/K/V scaled dot-product attention and the causal mask.
  - Multi-head attention and GQA.
  - Residual connections and RMSNorm/LayerNorm.
  - Feed-forward networks (GELU/SwiGLU).
  - **Mixture-of-Experts routing.**
- **Interactive:** clickable tokens with attention arcs, an N×N heatmap, a head selector and a causal-mask toggle.
  An MoE router showing which experts each token uses.
- **Build:** one complete transformer block in NumPy (attention with mask, multi-head, norm, FFN), checked against a reference.

### Module 4: How LLMs Generate (`04-generation-inference`) — new
- **Concepts:**
  - From the last vector to logits.
  - Softmax and decoding: greedy, temperature, top-k, top-p.
  - The generation loop.
  - The KV cache: what it stores and its memory cost.
  - Long context: attention's cost and position extrapolation.
- **Interactive:** temperature and top-p sliders on real next-token probabilities. A KV cache on/off comparison of
  compute and memory, using computed values.
- **Build:** a sampler that implements every decoding rule, and a generation loop with a KV cache that gives the same
  output as the loop without one.
- **Note:** Module 03's *logits*, *decoding* and *KV cache* steps moved here (short format, 2026-11-26); the deep conversion adds the generation loop and long context.

### Module 5: How Models Learn (`05-how-models-learn`) — new
- **Concepts:**
  - The next-token objective and cross-entropy loss.
  - Gradients and backpropagation, intuitively and on a tiny network.
  - SGD and Adam, learning rate and warm-up.
  - Batches, epochs and overfitting.
  - Scaling laws (Kaplan, Chinchilla) and compute budgets.
- **Interactive:** a loss-landscape stepper with a learning-rate slider. A Chinchilla calculator (parameters × tokens → compute).
- **Build:** train a tiny character-level model with hand-written gradients in NumPy, and watch the loss and samples improve.

## Part II: Using Pretrained Language Models

### Module 6: Text Classification (`06-text-classification`, was 04)
- **Concepts:** classification heads on representation models, embeddings + a classifier, zero-shot classification
  with label embeddings, classification by prompting, calibration and confidence.
- **Interactive:** a 3-way comparator (fine-tuned head vs. zero-shot embeddings vs. a prompted LLM) on banking
  support tickets, with measured latency and accuracy.
- **Build:** a logistic-regression head on real embeddings, a zero-shot classifier, and an evaluation with precision, recall and F1.

### Module 7: Text Clustering and Topic Modeling (`07-clustering-topics`, was 05)
- **Concepts:** document embeddings → dimensionality reduction (UMAP) → density clustering (HDBSCAN) → topic words
  (c-TF-IDF / BERTopic) → naming topics with an LLM.
- **Interactive:** a 2-D cluster scatter plot with `min_cluster_size` and outlier controls.
- **Build:** k-means vs. density clustering on real embeddings, and c-TF-IDF topic words.

### Module 8: Prompt Engineering and Structured Outputs (`08-prompt-engineering`, was 06)
- **Concepts:** the parts of a prompt (role, context, instruction, format), zero-shot vs. few-shot in-context learning,
  chain-of-thought, prompt chaining, structured outputs (JSON Schema, constrained decoding), validating and retrying.
- **Interactive:** a modular prompt builder and a probability inspector (Connect-my-Ollama live mode).
- **Build:** a prompt template engine, plus a validator that checks model output against a JSON schema and builds the retry prompt.

### Module 9: Semantic Search and RAG (`09-semantic-search-rag`)
- **Concepts:**
  - Chunking strategies.
  - BM25 vs. dense retrieval, and hybrid fusion (RRF).
  - Vector indexes: exact search vs. HNSW / approximate nearest-neighbour search.
  - Metadata filters.
  - Bi-encoder vs. cross-encoder reranking.
  - Query rewriting.
  - Retrieval metrics (Recall@K, MRR, NDCG).
  - Grounded generation with citations, and faithfulness checks.
- **Interactive:** a RAG pipeline explorer (chunk size, hybrid on/off, reranker on/off), with retrieved chunks and
  cited answers.
- **Build:** BM25 from scratch, dense search, RRF fusion, Recall@K and MRR on a labelled query set, and a grounded prompt with citations.

### Module 10: Agents and Tools (`10-agents-tools`)
- **Concepts:**
  - Tool schemas and function calling.
  - The ReAct loop (thought → tool call → observation → answer).
  - Conversation memory: full buffer, sliding window, summary.
  - Retrieval as a tool, and agentic RAG.
  - MCP (Model Context Protocol).
  - Failure modes (loops, bad arguments, unsafe actions), and evaluating agents.
- **Interactive:** a memory-eviction simulator with real token counts, and a ReAct loop stepper.
- **Build:** a tool-calling agent loop with a scripted model, argument validation, a step limit and a memory policy.

### Module 11: Multimodal LLMs (`11-multimodal-llms`)
- **Concepts:** vision transformers (image patches as tokens), CLIP contrastive alignment and its shared embedding
  space, projection layers (BLIP-2 / LLaVA style) that feed image tokens into a text decoder, and document images (OCR-free reading).
- **Interactive:** an image-to-patch grid with patch similarity to candidate captions in CLIP space.
- **Build:** cut an image into patches and embed them with a projection, then do zero-shot image classification with CLIP-style similarity.

## Part III: Training and Fine-Tuning Language Models

### Module 12: Creating Text Embedding Models (`12-training-embeddings`)
- **Concepts:** contrastive learning, positive pairs and hard negatives, multiple-negatives ranking loss, bi-encoder
  vs. cross-encoder training, and evaluating embeddings.
- **Interactive:** a contrastive vector-space stepper (anchors and positives pull together, negatives push apart).
- **Build:** the in-batch negatives loss and its gradient, and a few training steps on a toy embedding table.

### Module 13: Fine-Tuning Representation Models (`13-finetuning-encoders`)
- **Concepts:** full fine-tuning vs. frozen layers, few-shot contrastive fine-tuning (SetFit), trainable parameters
  vs. compute, and overfitting and validation.
- **Interactive:** a layer-freeze and data-size explorer, using published or captured results only.
- **Build:** count trainable parameters per freezing choice, then train a head on frozen features with early stopping.

### Module 14: Fine-Tuning Generation Models (`14-finetuning-generation`)
- **Concepts:**
  - SFT with chat templates.
  - LoRA (W + ΔW = W + A·B) and QLoRA (4-bit base + adapters).
  - Preference alignment: RLHF with a reward model vs. DPO.
  - Evaluating a fine-tune.
- **Interactive:** a LoRA rank explorer (r = 4…64, showing exact parameter counts and memory), and a DPO chosen-vs-rejected
  log-probability stepper.
- **Build:** a LoRA layer in NumPy (parameter count, merged weights), the DPO loss, and chat-template formatting with loss masking.

### Module 15: Reasoning Models and Distillation (`15-reasoning-distillation`) — new
- **Concepts:**
  - Test-time compute: chain-of-thought, self-consistency, and best-of-N with a verifier.
  - RL fine-tuning on verifiable rewards (PPO vs. GRPO).
  - Distillation from a large teacher to a small student.
  - Synthetic data and its risks.
- **Interactive:** a self-consistency and best-of-N explorer (accuracy vs. number of samples, using measured results).
- **Build:** majority voting and best-of-N with a verifier, GRPO group-relative advantages, and a distillation loss (KL to the teacher).

## Part IV: Production Inference & Guardrails

### Module 16: Serving and Inference Optimization (`16-inference-serving`)
- **Concepts:**
  - Prefill vs. decode.
  - **Quantization:** FP16, INT8, INT4 and GGUF, and the accuracy cost.
  - FlashAttention (IO-aware tiling).
  - PagedAttention.
  - Continuous batching.
  - Speculative decoding.
  - Throughput vs. latency, and memory budgets.
- **Interactive:** a GPU memory and request-scheduler simulator, with every number computed from model and GPU sizes.
- **Build:** a weight quantizer and dequantizer with error measurement, a KV-cache memory calculator, and a speculative-decoding acceptance simulation.

### Module 17: Evals, Guardrails and Failure Modes (`17-evals-guardrails`)
- **Concepts:** golden datasets, deterministic assertions vs. LLM-as-a-judge (and judge bias), hallucination and
  faithfulness checks, defenses against prompt injection, PII handling, and routing by latency, cost and quality.
- **Interactive:** a guardrail and eval pipeline sandbox (injection, PII, ungrounded queries).
- **Build:** an eval harness (golden set, assertions, a scoring rubric), a PII redactor and an injection detector,
  each with measured precision and recall.

### Module 18: Capstone — Document Intelligence Pipeline (`18-capstone`) — new
- **What you build:** an end-to-end system for messy business documents:
  1. read and chunk the documents;
  2. extract fields into a validated JSON schema with a local model (Ollama);
  3. score confidence and send low-confidence fields to human review;
  4. index the documents for retrieval;
  5. answer questions with citations;
  6. measure everything with a golden-set eval.
- **Format:** a guided project, not six-section steps. Each milestone has an in-page Python part and checks, plus a
  "Run it locally" version on a real model, with captured output.
- **Uses:** Modules 2, 6, 8, 9, 10, 16 and 17.
